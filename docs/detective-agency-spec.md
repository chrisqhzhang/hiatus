# 偵探事務所（暫名 *Case Desk*）開發規格 v0.1

> 日期：2026-11-23 ｜ 目標：2026-01 底上線 MVP（CrazyGames + GameDistribution）｜ 開發：1 人 + AI 編碼代理

---

## 0. 一句話

在一間逐步擴張的偵探事務所裡，每天破解一宗**時間軸格子推理案**：在平面圖上推出每位嫌疑人在各時段的位置，找出唯一與死者獨處的人。破案賺取聲望與資金，招募偵探、升級事務所、解鎖城市新街區。

## 1. 設計原則

1. **純邏輯、唯一解、不靠猜**：每題必有唯一解，且可只靠推理得出。
2. **一局 3–8 分鐘**：配合網頁平台的遊玩時長。
3. **養成服務於回訪，不阻擋解謎**：不設體力，任何題都能免費玩。
4. **原創 IP**：角色、城市、文字、美術全原創；不使用任何既有作品的名稱、關卡或版面。

## 2. 核心玩法：時間軸格子推理

### 2.1 案件結構
| 元素 | 規格 |
|---|---|
| 平面圖 | N×N 格（MVP：5×5、6×6；後續 7×7、8×8），分成 4–7 個**房間** |
| 物件格 | 門、窗、桌、床、樓梯等；部分格不可站人（牆內家具），部分有語意（「窗邊」「門口」） |
| 嫌疑人 | N 人（含死者 1 人），每人有名字、職業、1 項特徵（左撇子、高個子…） |
| 時段 | MVP 1 個時段；**v0.2 起 2–3 個時段**（20:00 / 21:00 / 22:00），這是與同類遊戲的主要差異 |
| 擺放約束 | 每時段：每行、每列各恰好 1 人；嫌疑人只能站在可站格 |
| 移動約束（多時段） | 相鄰時段之間，同一人只能留在原房間或移到**相鄰（有門相連）**的房間 |
| 破案條件 | 案發時段中，與死者同房且房內只有兩人者為兇手 |

### 2.2 線索類型（生成器詞庫）
| 類型 | 例 |
|---|---|
| 位置 | 「管家在書房。」「園丁不在任何窗邊。」 |
| 相對 | 「廚師在女僕的正北方某處。」「醫生與律師在同一列。」 |
| 物件 | 「伯爵夫人坐在椅子上。」 |
| 房間計數 | 「21:00 時圖書室有 2 人。」 |
| 否定 | 「上校從沒進過溫室。」 |
| 時間（多時段） | 「女僕 20:00 和 22:00 在同一房間。」「管家 21:00 離開了廚房。」 |
| 證物（養成解鎖） | 「泥腳印：兇手案發前到過花園。」 |
| 證詞矛盾（v0.3） | 一位嫌疑人的證詞為假，玩家需找出說謊者 |

### 2.3 操作
- 點格子：循環標記「×（排除）→ 嫌疑人頭像 → 空」；長按/右鍵選指定嫌疑人。
- 線索可點擊標為「已用」。
- 自動檢查衝突（可在設定關閉，關閉時破案獎勵 +20%）。
- 撤銷 / 重做無上限。

## 3. 謎題生成器（核心資產）

**流程**
1. 隨機生成平面圖：房間分割（區域生長）＋物件放置。
2. 隨機生成合法解（擺放＋移動約束），指定死者與兇手並確認破案條件成立。
3. 從線索詞庫抽出「對解為真」的線索，逐條加入，直到**求解器判定唯一解**。
4. 逐條嘗試刪除線索，若仍唯一解則刪除（最小化）。
5. **難度評分**：用「人類技巧型求解器」計算所需推理技巧層級（單點排除 → 行列鎖定 → 房間計數 → 跨時段推理 → 假設鏈），取最高層級與步數加權。
6. 輸出 JSON：平面圖、嫌疑人、線索、解、難度、種子。

**技術**
- 求解器：回溯＋約束傳播（位元遮罩）；6×6×3 時段需在 < 200 ms 內判定唯一性。
- 生成器在離線管線批量產出（Node 腳本），**不打包進前端**。
- 文字生成：線索用模板＋多語言字串；劇情短文由 AI 起草、人工校閱後入庫。

## 4. 養成系統

### 4.1 貨幣
| 貨幣 | 來源 | 用途 |
|---|---|---|
| 聲望（XP） | 破案、無提示破案、連續打卡 | 事務所等級 → 解鎖街區、偵探欄位 |
| 資金（軟貨幣） | 破案、每日任務、看獎勵廣告×2 | 升級辦公室、招募偵探 |
| 卷宗碎片 | 週連載案件、季節活動 | 解鎖收藏卷宗與劇情 |

### 4.2 偵探（提示技能＝角色）
| 偵探 | 技能（每案限次） |
|---|---|
| 新人助手（初始） | 揭示 1 個錯誤標記 |
| 法醫 | 揭示 1 人在 1 時段的位置 |
| 檔案員 | 標示下一步可用的線索 |
| 老刑警 | 排除 1 間房的所有不可能格 |

偵探可升級（次數 +1、冷卻縮短）。技能用完可**看獎勵廣告**補 1 次。

### 4.3 事務所與城市
- 辦公室：3D/2.5D 小場景，升級家具（純視覺＋小加成，如資金 +5%）。
- 城市地圖：5 個街區（舊城、港口、大學、莊園、劇院），每區有專屬平面圖主題、嫌疑人類型、連載劇情。

### 4.4 內容節奏
| 類型 | 頻率 | 留存作用 |
|---|---|---|
| 每日一案 | 每天 1 題（全球同題，可比時間） | 打卡、排行榜 |
| 自由案件 | 無限（依等級難度） | 填充時長 |
| 週連載 | 每週 1 章（3 案） | 劇情牽引回訪 |
| 季節活動 | 節日（情人節、復活節、萬聖節…） | 接熱點、換膚 |

## 5. 變現

- **獎勵廣告**：補提示、資金 ×2、每日任務重刷。
- **插頁廣告**：僅在案件之間，至少間隔 3 分鐘，新玩家前 2 案不出現。
- 依平台 SDK（CrazyGames SDK、GameDistribution SDK）實作；平台內購上線後再加「去廣告＋卷宗包」。

## 6. 美術方向與 3D／Shader 決策

**決策：2.5D——解謎盤面為 2D 正交視角，氛圍全由 Shader 處理。不做全 3D 或純 Shader 場景。**

| 方案 | 優點 | 缺點 |
|---|---|---|
| 純 2D | 開發最快、可讀性最好 | 視覺辨識度低，易被換皮 |
| **2.5D（推薦）** | 盤面清晰；Shader 做出黑色電影風格（體積光、雨夜、紙張質感、膠片顆粒），風格辨識度高、資產量小 | 需寫 Shader，工作量中等 |
| 全 3D／純 Shader（SDF raymarching） | 很有特色、檔案小 | 網頁平台大量玩家用低階筆電與學校 Chromebook，GPU 負擔大會掉幀；格子可讀性差；鏡頭與點擊判定複雜；3 個月內風險過高 |

**規格**
- 渲染：WebGL2，Three.js 正交相機（或 PixiJS ＋ 自訂 filter）。
- 盤面：平面網格，房間地板／牆以程序化 Shader 材質（木地板、磁磚、地毯）生成，不需貼圖資產。
- 後處理：暈影、顆粒、色調映射；**畫質三檔**，首次啟動依 FPS 自動降級。
- 人物：扁平立繪頭像（AI 起草 → 人工統一風格），非 3D 模型。
- 效能預算：首包 < 5 MB；低階設備 ≥ 50 FPS；載入 < 3 秒。

## 7. 技術架構

| 層 | 選擇 |
|---|---|
| 語言／建置 | TypeScript、Vite |
| 渲染 | Three.js（正交）＋自訂 GLSL |
| UI | 輕量 DOM 覆蓋層（或 Preact） |
| 謎題資料 | 預生成 JSON；每日案件從靜態 CDN 取得（例：Cloudflare R2），**前端內建 60 天備援題庫**以符合不允許外連的平台 |
| 存檔 | 平台 SDK 雲存檔（若有）＋ localStorage 備援，全部 try/catch |
| 多語言 | i18n 字串檔；首發 en，v0.2 加 zh-Hant、zh-Hans、fi，之後 es、ja |
| 數據 | 平台後台 ＋ 自建匿名事件（不收個資、不用第三方 cookie） |

**目錄**
```
/src/game      盤面、輸入、規則檢查
/src/meta      養成、貨幣、偵探、城市
/src/render    Three.js 場景、shaders/
/src/platform  CrazyGames / GameDistribution 適配層
/tools/gen     生成器、求解器、難度評分（Node）
/content       案件 JSON、劇情、i18n
```

## 8. 數據事件（匿名）

`session_start`、`case_start{id,difficulty,type}`、`case_complete{id,time,hints,errors}`、`case_abandon{id,step}`、`hint_used{detective}`、`ad_rewarded{placement}`、`ad_interstitial`、`level_up{lvl}`、`daily_streak{days}`

**關鍵指標與初始目標（估計值，上線後以實際分佈校準）**
| 指標 | 目標 |
|---|---|
| 首案完成率 | ≥ 70% |
| 平均遊玩時長 | ≥ 10 分鐘 |
| D1 / D7 留存 | ≥ 20% / ≥ 8% [UNCONF：網頁平台基準需在平台後台對照] |
| 放棄點 | 單題放棄率 > 30% 即調整難度曲線 |

## 10. 代理任務拆分（依序）

1. 建置骨架：Vite + TS + Three.js，平台適配層 stub。
2. `tools/gen`：資料結構、求解器（含唯一性判定），單元測試（已知題目）。
3. 線索詞庫與生成器、最小化、難度評分；輸出 200 題並統計難度分佈。
4. 盤面渲染與輸入（標記、撤銷、衝突提示）。
5. 案件流程：載入 JSON → 解題 → 結算畫面。
6. 養成：貨幣、等級、偵探技能、存檔。
7. Shader：程序化地板材質、後處理、畫質分級。
8. 廣告與平台 SDK 接入、數據事件。
9. i18n、效能檢查（低階設備測試）、上架素材（封面、截圖、描述）。
